# term-attach-resilience — 规格（delta）

## Purpose

约定 term attach 劣化路径上的可观察韧性行为：attach 后 TUI 画面完整性保障、raw 腿断链自动重连、退出前终端查询应答排空。覆盖 CLI raw 腿路径（surface/App 腿与 wire 字节不在本能力面内）。

## ADDED Requirements

### Requirement: attach 后的 TUI 全屏重绘保障

raw 腿 attach 到几何未变的运行中会话时，系统 SHALL 在回放完成后迫使屏上应用重绘完整当前屏：先施加一列差（sentinel 尺寸）、经一段足以让应用处理信号的间隔、再恢复真实尺寸；恢复动作 MUST NOT 覆盖间隔期间发生的真实尺寸上报，也 MUST NOT 作用于已结束或已换代的会话，且 MUST NOT 在恢复失效时将会话尺寸停留在 sentinel 值。几何真实变化的路径 SHALL 保持既有行为（一次真实 SIGWINCH 即足以触发重绘），MUST NOT 因本能力引入新的过渡渲染瞬态。一次 attach SHALL 恰好形成一个完整哨兵往返（判据计数 +1）。

#### Scenario: attach 到差分渲染 TUI 画面完整
- **WHEN** 客户端 attach 到一个运行中的全屏差分渲染 TUI 会话（本地窗口几何与会话几何相同）
- **THEN** 回放完成后客户端在数百毫秒内收到应用的全屏重绘输出，静态内容与动态内容均完整可见，无需用户手动 resize

#### Scenario: 几何真实变化的路径无新增瞬态
- **WHEN** 会话发生真实几何变化（用户 resize、异几何腿接入、重选举应用新尺寸）
- **THEN** 应用按新几何重绘一次到位，不出现「按中间列宽渲染并停留数百毫秒」的过渡画面

#### Scenario: 间隔期间真实 resize 让位
- **WHEN** 哨兵间隔期间用户真实调整了窗口尺寸（新的 RESIZE 上报到达）
- **THEN** 会话采用用户上报的真实尺寸，延迟的恢复动作放弃执行，不出现旧尺寸覆盖新尺寸

#### Scenario: 间隔期间会话终结则恢复跳不执行
- **WHEN** 哨兵间隔期间会话结束或同名重建
- **THEN** 延迟的恢复动作不作用于已死/换代会话，不产生跨代误伤

#### Scenario: 恢复跳失效不遗留 sentinel 尺寸
- **WHEN** 延迟恢复动作无法按期执行（如线程创建失败）
- **THEN** 会话尺寸立即回到真实值，不停留在 sentinel 列宽上运行

#### Scenario: 多腿瞬态受限
- **WHEN** 哨兵往返期间有其他腿在观看同一会话
- **THEN** 其他腿至多观察到一帧按哨兵列宽渲染的过渡画面，随后恢复真实几何（与一次真实 resize 的瞬态同形）

### Requirement: attach 断链自动重连（远程面）

远程目标下，raw 腿发生链路级终结（读侧断链/EOF/流收尾、写侧失败）时，CLI SHALL 不退出进程：保持本地终端 raw 状态、向用户显示一行重连状态横幅、按有界退避周期重试接入同一会话；接入成功后走完整握手（清屏 + 回放 + 重绘保障），会话继续可用。由 `new`（创建并接入）发起的会话在重拨时 SHALL 降级为纯接入语义（不再携带创建/独占标志），保证创建型会话同样可自愈。以下终结 SHALL 照常退出（不重连）：收到 ENDED 帧（会话结束）、收到会话级错误（如会话不存在）、本地终端 I/O 失效、用户退出。本地面（同机直连）的链路终结 SHALL 走既有终局文案退出——对端即出口进程本身，其死亡意味着会话已不存在，重拨永无成功。等待期间分离键与用户退出 MUST 仍然有效，等待期到达的输入 MUST NOT 注入恢复后的会话。

#### Scenario: 网络中断后自动恢复
- **WHEN** 远程 attach 过程中网络中断，且随后网络恢复
- **THEN** attach 进程不退出；断链期间显示重连横幅；恢复后自动重新接入同一会话，画面重建，输入输出继续

#### Scenario: 创建型会话同样自愈
- **WHEN** 由 `new` 创建并接入的会话遭遇链路中断后重拨
- **THEN** 重拨以纯接入语义进行，不因会话已存在而被拒，会话继续可用

#### Scenario: 断链期间的会话真实结束
- **WHEN** 断链期间远端会话已结束（如子进程退出、会话被删）
- **THEN** 重连尝试获得会话级错误后以可行动文案退出，不无限重试

#### Scenario: 本地面断链即终局
- **WHEN** 本地面（同机直连）的连接终结
- **THEN** CLI 以既有可行动文案退出，不进入重连循环

#### Scenario: 用户主动退出仍然有效
- **WHEN** 断链等待期间用户触发进程退出信号（SIGTERM/SIGHUP/SIGQUIT 等）、在等待态按下 Ctrl-C 字节、或按分离键
- **THEN** CLI 退出/分离并还原本地终端，不继续重拨

#### Scenario: 断链期输入隔离
- **WHEN** 断链等待期间有输入到达本地终端（击键或终端应答）
- **THEN** 除退出/分离动作外这些输入被丢弃，恢复后不作为会话输入注入

#### Scenario: 重连不误判会话终结
- **WHEN** 流以 ENDED 帧收尾（服务端明示会话结束）
- **THEN** CLI 不进入重连，按既有 ENDED 文案退出

### Requirement: 退出前的终端输入排空

CLI 在任何退出路径还原本地终端设置之前，SHALL 对本地终端做一次有界排空：以小超时等待在途输入落队，随后丢弃全部排队输入（不区分形态）。排空 MUST 使断链退出时刻的在途查询应答不漏给 shell；其代价 MUST 有界（对任何退出路径引入的额外延迟不超过该小超时）。

#### Scenario: 在途应答不漏给 shell
- **WHEN** CLI 退出的同一时刻，本地终端刚为一条在途查询排好应答
- **THEN** 退出后 shell 提示行不出现应答乱码（无数字/分号残串）

#### Scenario: 排空代价有界
- **WHEN** 退出时本地终端没有排队输入
- **THEN** 排空步骤在不超过所设小超时的时间内返回，退出路径延迟有界且不可感知

#### Scenario: 排空不回显
- **WHEN** 排空窗内排队了任意形态的字节（应答或用户击键竞态）
- **THEN** 这些字节被丢弃且不回显到本地终端，与既有发送失败丢弃语义一致
