## 自行复核结论

方案方向成立：用 IP 直连、校验证书并钉卡的 DoH 补上系统解析器被 fake-IP 污染的缺口，STUN 候选惰性尝试；QUIC 正常和 panic 收尾均清绑定表，修复引用环的方向与回归证据相符。但当前还不能视为完全收敛，确认以下四项（F4 是既存结构在本批修复后仍然留下的问题）。

### F1 / P2：3 秒总期限没有覆盖 TLS 内部 IO 循环

位置：`crates/homeway-core/src/server/doh.rs:250-257`，同样影响 `read_http_response` 对 `StreamOwned::read` 的调用。

`remain()` 只在 `StreamOwned::write_all` 前设置一次 TCP 读写超时。rustls 会在 `complete_io`/`prepare_read` 内循环读 socket，直到握手或完整 TLS record 到达。每次 TCP read 都可以再次使用完整的 socket 超时；外层 HTTP deadline 检查在此期间得不到控制权。因此，握手或 record 持续慢速到达会突破 3 秒预算，阻塞当前公网探测以及后备候选；首轮 token 兜底又无超时地等待探测结束，会一并被拖住。

隔离复现：localhost 服务端每 500ms 发送 1 字节未完成 TLS record；客户端使用与生产相同的 rustls `StreamOwned<ClientConnection, TcpStream>`，TCP 读写超时均 3 秒。实测 **4.026s** 后因对端 EOF 返回，主评审复跑 **4.018s**，落盘证据工程再跑 **4.030s**；延长滴流会继续延迟。测试没有访问公网，也没有 TLS 证书验证绕过：客户端尚未收到完整握手记录。

建议：把绝对 deadline 放进 rustls 底下的 `Read + Write` 包装器，每次底层 IO 前检查并按剩余时间设置 socket 超时。补 TLS 握手/record 滴流测试。当前明文 Reader 测试仅验证调用返回后拒收逾期响应，不能证明阻塞耗时有界。

### F2 / P2：停止位与写入未串行化，旧世代仍可追加最后一条 token

位置：`crates/homeway-core/src/server/engine.rs:2265-2268`（manual 路径 `2117-2120` 同形），实际副作用在 `print_client_token` 的 `2492-2494`；兜底调用 `1043` 也没有读取 `pubep_stopped`。

新增停止位只在调用前采样。线程一旦越过检查进入 `print_client_token`，就可能在网卡枚举、锁、日志回调或调度期间被暂停；`shutdown` 置位后不 join 该线程，也没有与发布共用的临界区。新实例写完台账后，旧线程恢复仍可执行 `append_token`，使 `serve token` 的台账回落路径读到旧端点。仅在 helper 内再加一次原子 load 仍有相同 TOCTOU 窗口。

隔离复现：在 `git archive c8f56be` 副本中追加测试，从真实 `refresh_public_endpoint` 的 manual 路径起跑，借真实重复中继端点分支的 `dlogf` 回调设置 barrier，暂停在旧 `print_client_token` 追加前；置与 shutdown 相同的停止位，先用相同凭证追加新端点 token，再放行旧线程。测试 **1 passed**，主评审复跑同样通过，断言并打印：`PoC confirmed: stopped old generation became last_token after new generation appended`。这是直接验证 refresh 与台账交错的单测，并非完整 CLI restart 集成测试；普通 restart 沿用凭证，复现后果是最新端点倒退。

建议：用发布锁或受锁保护的世代号，让 shutdown 失效旧世代与最后一次有效性检查、端点写盘、token 追加串行化；兜底发布也走同一入口。补确定性并发回归，断言停用世代不能在新世代之后发布。

### F3 / P3：STUN6 字面量遗漏 IPv4-mapped 排除，阻断真正 IPv6 后备

位置：`crates/homeway-core/src/server/engine.rs:2330-2332`；成功后提前退出位于 `2213-2215`。

字面 IP 仅用 `is_ipv6()` 判族，因此 `[::ffff:<公网 IPv4>]:3478` 被当作 STUN6 候选，实际走 IPv4。若该服务器返回正常公网 IPv4 映射，循环即 break；后续 `global_v6` 才丢弃该结果，真正的 IPv6 后备不会再尝试。旧 `resolve_stun6` 和新 DoH 域名分支均排除 mapped，只有新增字面量分支遗漏。不影响默认域名候选，属显式配置边界。

隔离 harness 原样提取当前 `StunCandidates`，用字面量专用 stub 和脚本化回包验证候选选择与后备未消费；未对测试用地址发真实 STUN 请求。

建议：字面量入口与域名入口统一按“非 IPv4-mapped 的 IPv6”判族，并在接受成功回包前校验观测地址族；补 mapped 在前、真 IPv6 在后的回归。

### F4 / P2：中继注册线程独立持有 UDP 副本，shutdown 返回不代表端口已释放

位置：`crates/homeway-core/src/server/engine.rs:742-748`、`845-864`、`1140-1158`；`crates/homeway-core/src/server/relayleg.rs:119-145`。

`relay_sock_dup` 是公共 QUIC 监听 socket 的独立 fd 副本，由 detached 中继注册线程持有。shutdown 置停止位、join driver，但没有保存或 join 注册线程；`bridge.clear()` 只断开 QUIC 引用环，不能释放这份副本。事件通道断开会唤醒注册线程，但调用方没有等待它实际退出，重启重新 bind 仍可能抢在副本释放前，触发端口退让。这不是本批新引入的持有关系，却是“修复重启端口释放”仍未覆盖的残余。

隔离复现：真实 `ServeEngine::start`，独立 `/tmp` state、随机公共端口、仅回环中继目标、关闭 UPnP/STUN/DNS 外部探测。通过注册线程真实日志回调中的 barrier 控制其调度；`shutdown(Duration::ZERO)` 已返回，此时重绑仍是 **AddrInUse**；放行注册线程后立即可重绑。测试 **1 passed**，输出 `PoC confirmed: shutdown returned before relay socket dup closed; releasing relay worker freed port`。该实验验证 shutdown 的完成不变量缺失，不代表普通环境每次 restart 都会退让，也没有执行生产重启。

建议：保存注册线程的 join handle，停机先通知退出并等待其释放 fd，再允许新实例绑定；或将该 socket 的发送职责归到一个有明确收工序的 owner。新增带 relay 的整体引擎停机/重启回归；现有 QUIC 单体的正常/panic 断环测试不能覆盖这条独立持有路径。
