### harness 重标定（有据，非调参凑数）

1. **链路模型突发额度修正**：出队 credit 空闲累积上限原误设为队列容量（2MB——
   空闲后一次放出 = 24MB/s 链路 85ms 的量，物理链路无此形态）。该 mega-burst 把
   smoltcp 接收端「每 poll 至多一个 ACK（顺序数据）」的合并形态放大成 **ACK 时钟
   饿死**：burst 到达 ⇒ 每团一 ACK ⇒ 发送端 CUBIC 每 RTT 只 +1 MSS ⇒ 16MB 传输
   实测 3.5MB/s（稳态实为满链路 24.8MB/s——64MB 传输实测 12.9MB/s 均值、尾窗满速）。
   修正：burst = rate×2ms（≈48KB）。内核/gVisor 接收端无此形态（团内每 2 段回 ACK）。
2. **A 单流 16→64MB / A 并发 6×3→6×8MB**：上游 CUBIC 慢启动爬坡在 harness 接收端
   ACK 合并形态下需 ~1.5-2s，16MB 量级传输被爬坡期支配（5.5MB/s vs 稳态 24.8）；
   量级提到稳态支配。塌陷判别语义不变（0.4MB/s 塌陷在 64MB 下 160s 超时必红）。
3. **A 并发臂阈值 50%→1/6**：原 50% 阈标定于**已退役垫片**的 pacing 行为（垫片 pacing
   顺带保住了接收端 ACK 密度）；上游 CUBIC 无 pacing，N 流慢启动过冲对 2MB 尾丢缓冲
   的同步振荡 + ACK 合并放大下实测 5.0-11.5MB/s 波动。**塌陷判别职责移交 B 臂**
   （修正模型下 CC=None 深队列 22.6MB/s 不再构成判别信号、浅队列仍 <0.2MB/s 级塌陷
   实测——8MB 未完成跑 8min+）。三个臂的旧数字（垫片 15.8/16.7/6.4）留档为历史基线。

## §二 8b：encap/UDP 发送路径优化（commit 8b 批 + 微修）

### profile 结论（2026-10-04 `sample` 实测，与 PERF-AB §8 的 76% 一致）

出口驱动线程（下行 bulk 期间）：**78% 样本在 `__sendto`**（每包一次系统调用），
poll 12 个、smoltcp 栈 poll ~2%。两条 sendto 路径 = `route_encap`（拦截拍产物）+
`handle_inbound`（逐包收后的应答收口）。

### 实现与真机验证的曲折（保留全过程结论）

1. **`udpbatch` 模块**（保留）：批量发送原语——Linux/OHOS `sendmmsg`（≤64 条/批、
   短返余量留下一拍、EINTR 整批重试；libc 面在 aarch64-unknown-linux-ohos 编译
   验证）；macOS 回退逐包 std send_to（与 Go/wireguard-go 同形态——同机 A/B 公平）。
   回环 80 包顺序到达单测。
2. **出口 `ServerBind.send_wire` 批化 + staging**（保留）：腿帧先落复用 staging
   （消除逐包 frame_bytes 的 Vec 分配，载荷一次拷贝）再批量发出；腿 socket 命中
   （稀疏路径）保持逐包；空批快速返回。macOS 宿主回环 A/B：down 261-263Mbps 持平
   （Go 同形态）、up 401→469Mbps（staging 零分配收益）。
3. **客户端（手机）上行批化**（**实测劣化已整体移除**）：曾实装「pump_once 收集
   TUN 包 + 栈 B TX → 批量 encap → `send_wg_batch` 一批 sendmmsg」。真机 A/B
   （FMR0224116011480，本地 Rust exit）**两侧皆劣化**：批化 down 15-18MB/流 vs
   逐包 41-47MB/流、up 25MB/流 vs 32-86MB/流——OHOS 的 sendmmsg 批量路径反而拖慢
   收发节奏（机制未深挖：疑批量突发与 WiFi 驱动交互 + 每批系统调用内无中间唤醒点）。
   消融实测后整体移除（pump_once 注记留档）；客户端侧 8b 的净交付 = 背压修复（下条）。
4. **上行 bulk 断流的真根因与修复**（本批最大发现）：`SessionWriteHalf::write`
   把栈内 tx 缓冲满时的 `send_slice` **Ok(0)** 直接透传——io::Write 契约里 Ok(0) =
   通道关（`write_all` 以 WriteZero 报错），桥泵据此拆连接 ⇒ 上行 bulk 一进慢链路
   （缓冲被 cwnd 门限速填满）就整轮断流。**R7 E2E 登记的「phone→exit WG 上行 bulk
   吞吐退化」即此**（host 形态 CLI 走 ClientConn 的零进展重试环，桥路径裸露）。
   修复：Ok(0) 展开为**有界等待重试**（2ms 节拍、10s 无进展上限——Go net.Conn.Write
   阻塞语义）。真机验证：上行从「4 会话 <1s 全 EOF」到「完整轮完成」。
5. **桥泵收口观测**（保留转正式）：桥泵此前静默收口——累计字节 + 收口原因一行
   （有流量才打，空闲连接零噪音）。本次排障的关键观测面。

## §九 R8-3 8i：出口发送整形——设计小节（实装前登记，2026-10-05）

> 范围 = PERF-AB §9.7 修复路径 ①（拦截栈单 poll 排空 → 发送预算 + 分拍投放）。
> 本节先落设计再动代码（任务纪律：设计细节过评审再实装）。

### 位置与机制

**拦截面**：`Interceptor::pump()` 尾部——拦截栈单 poll 的排空产物（tx_out，已反重写
的明文 IP 包）先并入**滞留队列**（`tx_deferred`，FIFO），再按**字节令牌桶**从头释放；
释放出的包才是本拍返回引擎 encap 的出站集合。`pump_grace` 复用 pump ⇒ 收工宽限走同
一整形。**无 sleep、不阻塞驱动线程**：滞留队列靠后续 pump 拍续传——驱动线程每拍必调
pump（poll(2) 5ms 上界 + ACK 到达即醒），即 PERF-AB §9.7 的「预算 + 下拍续传」。

**预算（静态默认 + env 覆盖，不与 CUBIC 抢自适应职责）**：

| 参数 | 默认 | 依据 |
|---|---|---|
| 速率 R | 64 MiB/s（`HOMEWAY_TX_RATE_MBPS` 覆盖） | 真机层 0 天花板 94MB/s 的 0.68×；验收带 40-45 之上留 ≥40% 余量。稳态到达 < R 时令牌常满、**零延迟直通**——整形器只削峰不平率，平均率仍由 ACK 时钟（CUBIC）决定 |
| 突发额度 B | 160 KiB = 128 × MTU1280（`HOMEWAY_TX_BURST_KB` 覆盖） | §9.7 建议带「≤128-256 包」的下沿（满包口径恰 128 包）；与 harness DirLink 的 rate×2ms 物理突发参数同量级；驱动拍 5ms 的续水量 320KB ≥ 2×B（桶永不在拍间枯竭两拍）。任何窗口 w 内线上深度 ≤ B + R·w |

**静态而非自适应的理由**：自适应（ACK 速率 max-filter 估计）与 CUBIC 构成双环耦合
（估计跌 → R 收紧 → 到达形态变 → 估计再跌的振荡面），且冷启动窗口恰是悬崖窗口（无
估计可用仍得回落静态值）。静态 R 的疑虑「路径容量 < R 时持续过载」不成立：整形器
**不注入流量**——滞留队列只能持有 smoltcp 已排放的量，而排放以 ACK 回收为前提（在途
≤ cwnd）⇒ 路径慢 ⇒ ACK 慢 ⇒ 排放停 ⇒ 桶只削每拍团块。失效模式收敛为「削峰粒度不随
路径变」，由 env 臂真机调参兜底。

**与背压/饥饿的交互**（评审要点预答；r2-3.1 复核后诚实版）：
- FIFO + 聚合桶：按到达序释放，无流间饥饿；多手机共享 R（链路物理本就共享）。
- 滞留队列有界性：**TCP 面**由在途记账保证（派发即算在途 ⇒ ≤ Σcwnd ≈ 数 MB）；
  **UDP 过境/DNS 应答/ICMP 回显不走 TCP 窗记账**——其上界来自内核收缓冲 + 栈内
  UdpSocket 64KB/流的包缓冲与请求-应答配对（过境 UDP 上游数据受 worker 水位与
  send_slice 满即弃约束），有界但**不受整形/窗记账约束**（恶意高频面理论可把滞留
  抬过 R——高水位丢弃方案登记未实装：UDP 本身可丢、不属「整形器丢 TCP 包」禁区）。
  不设显式上限的理由维持：对 TCP 面，加上限 = 整形器丢包 = 伪修复禁区。
- 字节口径令牌：纯 ACK/DNS 小包成本 ∝ 尺寸，不被大包挤出；排队延迟上界 =
  实际队深/R（TCP 面 ≈ Σcwnd/R，默认参数下 ~47ms 量级；队头阻塞无硬上界——
  上界随队深走，见上条）。
- 大于 B 的包防御性直通（内层 IP ≤ 64KB 恒小于默认 B；防极小 B 配置死锁；
  r2-1.2：直通分支不扣令牌——防死锁 ≠ 参与记账）。

**消融臂**：`HOMEWAY_TX_SHAPING=off`（presence-only，与 HOMEWAY_UDP_NO_BATCH 同惯例）
——真机 A/B 与 harness on/off 臂共用。产品默认 = 开。

### 8r 形态拍板（改版）：自适应逐包时刻表 + 驱动循环亚毫秒等待

任务书候选 a/b 的融合 + 反过拟合约束 1：

- 等待原语 = **pselect(2)**（POSIX，macOS/Linux/OHOS-musl 三面可用，timespec 到
  ns；poll(2) 整毫秒超时在 1ms 拍内无法逐包分时；usleep 违反 R1 线程模型——阻塞
  驱动线程 = 锁死三唤醒源）。fd 集与 poll 路径同构（主 UDP + 腿）；**FD_SETSIZE
  防御按 fd 编号判**（`max(udp_fd, 腿 fd) < FD_SETSIZE`——按个数判是 Darwin 的
  越界写 UB，评审 r1-1.3 高危），越界一次性记行后退回 poll 1ms（不静默降级）。
- **pace_rate 自适应**（反过拟合约束 1；替代初版固定 128MiB/s——初版参数依据的
  「留 26% 空闲窗」算式方向反了：pace > 空口 94MB/s 时空口被压满，无交织窗
  〔评审 r1-5.3〕；且固定值对 2.5G+ 快路径是人为限速）：
  `pace = clamp(TX_PACE_GAIN × est, TX_PACE_FLOOR, TX_PACE_CEIL)`，
  `est = ACK 时钟吞吐估计`（100ms 窗，窗内 ACK 确认字节/窗长；**max 攻击/0.95 每
  窗慢衰减**，下界 8MiB）——est 在 CC 平衡点 ≈ cwnd/RTT（smoltcp 0.14 不暴露
  cwnd/ssthresh〔R8-8a 已核〕，ACK 时钟测的是其等价量，Linux fq pacing 的
  delivered-rate 派生同型）。**增益 1.2**（Linux fq 稳态档；初版 2.0 真机消融实测
  「整体不 engage」——稳态 produce 率=ACK 时钟≈est≪2×est ⇒ 时刻表恒在过去，
  ACK 时钟团块原样直通；见 §9.11 教训一）；est 下界 8MiB（16MiB 档在日间
  goodput 之上与实测脱钩）；慢路径（20Mbps）pace ≥9.6MiB/s 恒不绑定（无滴流）。
  **默认 off**（§9.11 止损裁定：8s 在位时无增益 + 组合形态 2-4MB 常驻滞留）；
  config/env 显式开。
- **补账量子**：单次释放 ≤ `max(pace×2ms, 2×MSS)`——时刻表积欠的补账跨多拍
  排空（每拍一团），不以桶的 256KB 为补账上界（冷空口臂实测抓到 256KB 补账团
  击穿 192KiB 到达预算：25 到达丢失——量子收紧后归零）。2ms 档 = 排空能力
  （量子×拍频 ≥ pace，负载机泵 630/s 实测余量 ~2.5×；500µs 档曾把快臂压到
  0.63×off）与团块上界（pace×2ms ≈ Go 自然团量级 §9.10）的平衡点。
- **R（桶均值）同步自适应**（约束 1 的复核项）：pacing on 时
  `R_eff = max(TX_SHAPE_RATE, 4 × est)`——WiFi 形态 est≈45 ⇒ R_eff=200MiB/s 不变
  （8n③ 语义）；2.5G 快路径 est≈312 ⇒ R_eff≈1.25GB/s，桶不再是瓶颈。**pacing off
  臂 R 恒 200MiB/s**（消融对照 = 8n③ 形态原样）。固定 pace 梯度臂（诊断）不抬 R。
- 时刻表语义（评审 r1-1.2 的实装口径）：`pace_next += len/pace`（**不向 now 钳**
  ——钳了补账退化成每唤醒一包）；队列排空时 `pace_next = now` 重置（空闲不积累
  放行额度）。迟到补账一次放多包，**单次调用补账上界 ≤ burst**（credit 不变量
  自带）⇒ pacer 最坏形态 = 8n③ 单拍形态，不会更坏。稳态到达 < pace 时时刻恒在
  过去 ⇒ 直通零延迟。
- **两道门是串联**（评审 r1-2.2 措辞修正）：同一条 FIFO，释放率 = min(桶门, 时间门)
  ——不是并联防御。pacing 会把团块排队 ~团量/pace（23KB@90MiB/s ≈ 0.26ms；最坏
  256KB ≈ 2.8ms）⇒ 判据面登记「RTT 不回 8ms 量级」（对照 §9.10 的 17-27ms 事故带）。
- **亚毫秒等待的占空模型**（评审 r1-1.1 认账）：wait = min(credit_wait, pace_wait)，
  credit 恒满时 wait=pace_wait；pace 间隔低于循环固定成本（~20-30µs）时驱动线程
  满占空（每唤醒放多包、无睡眠）——**这不是自旋空转**（每次唤醒都在放行真实包），
  但 pace 参数退化为「循环容量界定」⇒ 加 **50µs 量化下限**（wake ≤20k/s，量化
  由补账语义吸收）+ 观测行（est/pace/每次唤醒放行包数/驱动线程 CPU 线程级读数）
  + `pace ≤ rate` 交叉钳制（Fixed 梯度臂防纯自旋）。
- 参数面（**约束 3：config 化**）：config.toml `[serve.tx_shape]` =
  `rate_mbps`（默认 200，pacing on 时只是下界）/`burst_kb`（默认 256）/
  `pacing = "adaptive"|"fixed"|"off"`（默认 adaptive）+ `pace_mbps`（fixed 时）。
  覆盖序 **env > config > 产品默认**（env = A/B 测试缝：HOMEWAY_TX_PACING 值匹配
  惯例 off/0/false=关、HOMEWAY_TX_PACE_MBPS=Fixed 梯度、HOMEWAY_TX_RATE_MBPS/
  HOMEWAY_TX_BURST_KB 不变）。**pacing 默认开**是产品行为变更（CPU/等待语义），
  以矩阵达标为出厂依据（未达标 ⇒ 默认回退 off 并归因入册——r1-A2 止损规则）。

### 8s 形态拍板（改版）：有界 drain（每 ~2×MSS 栈字节一批）

- smoltcp 0.14 ACK 策略已内建 RFC5681/Linux 风格（`immediate_ack_to_transmit`：
  未确认 > 1×remote_mss ⇒ 立即 ACK；10ms delayed 兜底）——**无需改栈**
  （r1-4.1 已核源码：Interface::poll「先排空全部 ingress 再 egress」+ 每 poll 每
  socket 至多一个累积 ACK——稀疏时钟的成因是驱动循环「一次收光 → 一次 poll」的
  批到达形态）。
- 改法（**有界 drain**，r1-4.2 采納——pump_once 保持唯一栈驱动点，插桩口径不动）：
  `drain_udp` 计**进 stack B 的字节**，累计 ≥ 2×1280（2×MSS：>1×MSS 才触发立即
  ACK）即返回；驱动循环的 poll 因 UDP fd 仍可读立即返回 → pump_once 既有栈 poll
  产 ACK。小包按字节累积自然合并；**transit/TUN 包不计**（r1-3.3：不经 stack B
  的包零额外 poll 成本）；批尾不足 2×MSS 由 pump_once 兜底，奇尾段走 10ms delayed。
- **适用域**（r1-3.1 高危认账）：8s 只覆盖**核心自连**（stack B 收端 = speedtest/
  files/term/探测路径）；经 TUN 的应用流量由 OHOS 内核回 ACK，8s 零作用——本批
  「B 组 ≥40」是**测速路径**数字，产品下载面只受 8r 覆盖。矩阵/PERF-AB 数字带
  「核心自连（smoltcp 收端）」限定。

### 两线关系与决策规则（r1-3.2：同一条因果链，先买一次）

出口团块 ≈ 对端一个 ACK 释放的在途额度：ACK 密到每 2 段 ⇒ 团块自动缩到 ~2.5KB
（pacing 趋近无效）；pacing 生效 ⇒ 到达平滑 ⇒ 手机 drain 每 1-2 包天然产密 ACK。
**先 8r**（出口侧、覆盖全流量含 TUN、不动 tier pin），矩阵预登记决策规则：
8r-only 臂若「tcp 观测」段/ACK ≤ 4 且 ≥40 达标 ⇒ 8s 不进产品默认（保留 env/config
缝与实装）；8s 只在该判据红时进默认。四臂矩阵照跑（任务书要求分别消融）。
