# 2026-10-23 `homeway update` 自更新批 —— 技术评审 + 代码评审记录

> 需求（用户）：`homeway update` 自动从 GitHub 拉最新 Release 完成替换与重启；
> 没有新 tag 时告知用户没有更新。
>
> 形态：原生新功能（无 Go 基线对应物——不是移植批，两道门按新功能口径走；
> 外部 reviewer 渠道按其使用纪律不在未明确要求时发起，本批用结构化自评，
> 实现者/评审者双角色分离，checklist 对齐 ROADMAP「评审协议」）。

## 一、技术评审（开工前设计要点）

### 需求拆解与可行性结论

| 子问题 | 结论 | 依据 |
|---|---|---|
| 恢复之前运行的模式 | **零额外状态**：统一进程零参启动按 config 期望态装配 serve/relay | `unified_cli::run_unified_state`：锁 → state → config → 角色装配；动态启停写回 config（`write_config_enabled`） |
| 替换运行中的二进制 | 同目录暂存 + `rename()` 原子盖写（运行进程持旧 inode，无 ETXTBSY） | Unix 语义；与 config 写回的原子纪律同构 |
| 谁拉起新进程 | launchd 主机 = KeepAlive；裸进程主机 = update 自己 setsid 自拉起 | `start_spawned_process` 既有件（按需拉起每天都在用）；阿里云生产本就是无自启动档 |
| 没有新 tag | `tag_name == cli_version()` → 打印「已是最新——没有更新」exit 0 | `HOMEWAY_CLI_VERSION` = tag 注入（release.yml） |

### 关键设计决策（含被否方案）

1. **HTTPS 客户端放 core（新模块 `minhttp`），不放 CLI** —— 被隔离门 ① 约束：
   cli/capi 不得声明 rustls。core 已有 rustls + webpki-roots（DoH 用），零新增依赖面；
   门同步扩为「同步 rustls 白名单两文件」（doh.rs + minhttp.rs，含清单自校准）。
2. **不复用/不改动 `server/doh.rs` 的 HTTP 读取件** —— 两面约束不同（DoH：钉卡 +
   POST + 64KiB 上限的生产 DNS 纪律件；本件：系统 DNS + GET + 重定向 + 调用方上限
   + 数 MiB 体）。为共享而重构生产 DNS 路径风险大于收益；偏差在 minhttp 模块头登记，
   收敛留待真有第三个消费者。
3. **不引新 crate**：flate2（tar.gz 解压）已是 workspace 依赖（core 已用）；sha2 /
   serde_json cli 已有。产物下载进内存（≈4MiB，64MiB 护栏）而非流式落盘——CLI 一次性
   流程，简单性优先。
4. **重启编排三档**（实测锚定）：守护未跑 → 只换文件；SIGTERM 后新 pid 持锁 →
   托管方已拉起（launchd）；锁空 + 进程已退 + 3s 宽限无人拉 → 自拉起。
   否决「daemon 内 execve 自替换」：多线程 exec 的锁 CLOEXEC 释放存在竞争窗口，且
   「停→拉」路径全部复用既有件。
5. **失败面全部前置**：下载/哈希/解包/烟囱任一失败 = 中止且现役不动；替换动作
   （rename）放在全部校验之后、守护重启之前。回退 = `<state>/cache/homeway.prev`
   放回原路径。
6. **阿里云不绕纪律**：GitHub 不可达主机在 fetch 阶段如实报错并指向 scp 路径
   （部署纪律 2026-10-21 第 3 条不因本命令松动）。
7. **windows fail-fast**：运行中的 exe 无法 rename 盖写（内核锁文件），明确报
   不支持而非半途而废。

### 拆步

minhttp（core）→ update_cli（cli）→ 接线/暴露 spawn 件 → 隔离门扩 → 单测 →
/tmp 三场景端到端 → 本地 CI（quick 全档）→ 文档（README/DEPLOY/ROADMAP/本记录）。

-p homeway-cli` 全绿（core lib 912/0、cli 73+5/0；一次与 clippy 并行跑出的单例 flake

**真网冒烟**（`--ignored` 手动档）：GitHub API latest over 真 TLS 通过（DNS→TCP→
握手→chunked JSON→tag_name）。

**/tmp 端到端三场景**（不影响任何真实文件/进程）：

## 四、代码评审（完工后，结构化自评）

按协议 checklist：

- **对齐完整性**：需求三要素（拉最新/替换重启/无更新提示）全落地且有端到端证据；
  与部署纪律的关系已登记（DEPLOY 第 6 条：自动化下载校验尾部，不绕 tag/Release 门）。
- **边界**：404/403（限流）/非 200 各自可行动文案；产物缺失列平台名；哈希不齐中止；
  烟囱不过中止；`pid<=0 || pid==self` 守卫；SIGTERM 失败给手动指引；20s 无人接手如实
  报告不假装成功；devel 构建显式提示后继续。
- **并发**：无共享态；锁语义全交内核（flock 随进程退出释放）；launchd 与自拉起的
  竞争用「新 pid 持锁即外部拉起 / 锁空 3s 宽限后才自拉起」消解（launchd KeepAlive
  重拉在亚秒级，宽限窗口内必然表现为新 pid 持锁）。
- **错误面**：core 侧 thiserror 枚举（`#[non_exhaustive]`）；CLI 侧沿仓惯例 String
  文案 + 可行动提示；任何失败路径都清理 staged 暂存文件。
- **Go 直译痕迹**：无（原生新功能，无基线对应物）；模块头写明与 doh 的偏差登记而非
  模仿；无多余 Arc/Mutex。
- **地道 Rust**：`Src<R: Read>` 泛型让 framing 可离线单测；重定向策略抽纯函数；
  ustar 解析借用切片零拷贝（返回目标条目才 to_vec）；`div_ceil` 对齐；测试用例自带
  ustar 写入器只进 `#[cfg(test)]`。
- **残留/豁免**：无。CHANGELOG 与版本号随发版批（本批源码完成未发布）。

## 五、已知边界与登记

1. 引导问题：现役二进制（≤v0.3.20）没有 update 命令——**下一次走完整发版链换装后，
   再往后的升级才可用本命令**（本批 ROADMAP 条目已注明）。
2. 阿里云：fetch 阶段报错并指向 scp 路径（不绕部署纪律）。
3. 非默认启动 flag（如 `--verbose`）的守护被自拉起后回到缺省形态（spawn 件只透传
   `--state`——既有语义，生产两台都是零参形态，无影响；完整复刻 argv 需守护记账，
   留待真有需求）。
4. GitHub API 未认证限流 60 次/小时/IP——手动运维频度无碍，403 有文案。
5. 隔离门 ① 白名单从 1 件扩到 2 件（本批唯一的门面变更，头注释 + Cargo.toml 注释
   同步登记）。
