1. **`reg.rs` 落点 = 设计 §1.2-M3 的备选 `homeway-core/src/reg2.rs`**（非「并入 `server/table.rs` 邻域」）。
   原因：K7 明令 `table.rs` **保留零改动**（QUIC 准入同走 `table.register`），并入会破坏该约束；
   且并入 = 内容改写 ⇒ 丢 R100 纯改名口径（§11.1 要求迁址件判 R100）。`reg2` 名 = 报文版本 v2
   （`"H2"` / MAC 标签 `hr-reg2`）的编码面，有语义不属遗留。**影响面小、就地解决 + 登记（本表）**。
2. **S0 单独不可编译（如实登记，不粉饰）**：S0 摘掉 `wtransport::frame` 后，relay 三文件仍指旧址；
   而 §15-4/§11-S0 要求 relay 面**独立 commit + 红线声明**（S0b 在后）⇒ S0 与 S0b 之间必然存在
   一个**不可编译的 commit 边界**。判据「`cargo test --workspace` 全绿」按 **S0+S0b 合并态**取
   （§1.5 的七步表里 S0+S0b 本就是**同一步**）。未加临时 `pub use` 垫片，理由：垫片会让 S0b 的
   红线 commit 混入非 relay 文件改动，破坏「红线小批」的可审计性。
3. **S0 连带触碰 `server/intercept/**` 2 个 import 行**（红线面之一）：`crate::wgcore::stackb::{TunDevice,StackB}`
   → `crate::stackb::…`。这是 §1.2-M2 迁址的必连改动（intercept 是该模块的**生产**消费者与 E2E 测试泵），
   除这 **2 行**外 intercept 其它面零改动（`git show fbd2589 -- crates/homeway-core/src/server/intercept/mod.rs` 即证）。
   **本棒据此对第二条红线面也做显式声明**（任务书只点名了 relay 面；此处主动扩声明，防漏审）。
4. **`server/engine.rs` 的局部变量改名**：`let mut reg2 = …` → `let mut reg_pkt = …`（5 行同函数内）。
   原因：新模块名 `reg2` 与该局部变量同名 ⇒ 同一行出现 `Vec::with_capacity(reg2::REG_LEN)` 的
   阅读歧义（Rust 语义合法但人读易错）。属**纯可读性改名**，行为零变。
5. **`smoltcp` `socket-tcp-reno` 未删**（设计 §7.3-2 的「M5 可同批删」）：复核已完成（零消费者），
   删除动作判为 **S3/S4 面**（须同批跑出口 intercept TCP 回归 + 重测 `[size]`）。见 §5-2。
