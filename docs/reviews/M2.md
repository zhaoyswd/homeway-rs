## 1. 差异登记（S4 落 + S6 增补）

### 1.1 每源闸阈值：设计 §3.3-6 / S3-2 的「正常赛跑 ⇒ 两计数为 0」与实测冲突（**已裁**）

- **设计原文**（§3.3-6）：≥3 候选的**正常**赛跑连续 N 轮（≥5）⇒ `retry_sent = 0` 且每源闸
  `flood_refused = 0`；依据 = §3.1-②「只计**未完成/被拒**的尝试 ⇒ 正常赛跑会完成 ⇒ 不计数」。
- **实测（S3 收口；真岛 + 真出口，3 个同址候选 × 4 轮）**：客户端在候选**完成前** abort 输家
  （`client/race.rs` 的 `abort_all` 语义）⇒ 出口侧落 `HandshakeOutcome::Failed` ⇒ 计入每源闸
  （不销账）：`handshake_failed = 5`、`retry_sent = 4`、`flood_refused = 5`，第 4 轮岛侧拿到
  `NoCandidate`。设计 §3.1-② 的前提只对「**候选完成后再被收掉**」的形态成立（回环 3 候选 × 8 轮
  该形态 ⇒ 两计数 = 0；已落单测 `exit::tests::normal_races_do_not_trigger_retry_or_gate`）。
- **裁定（主会话；设计 §14-1，2026-10-09）**：①**不放宽计数集**（攻击者同样能 abort ⇒ 任何
  「豁免 abort」的放宽都可被规避 = 逃逸面）；②每源阈值缺省 `per_src_fails` **10 → 16**（窗保持
  10s；单轮 3 候选消耗 `N−1 = 2` 次预算 ⇒ 16 允许约 5 次赛跑/窗；攻击者仍被束在 ≤16 次握手/10s/源，
  有界性不变）；③判据措辞改写为「**正常赛跑在阈值内 ⇒ 不触发闸**（`retry_sent` 可为 0；
  `flood_refused` 只有在超过 `per_src_fails` 后才增长）」；④（可选）赛跑输家显式优雅关闭
  ——**S4 实测后按「别硬做」收口**（做不到，理由见 §1.2 末条）。
- **落地与证据（S4）**：`crates/homeway-quic/src/exit/admit.rs` 的 `PER_SRC_FAILS_DEFAULT = 16`；
  正面用例 `exit::tests::race_abort_form_stays_within_gate_budget`（3 候选 × 5 轮 abort 形态 ⇒
  `flood_refused = 0`）+ 对照臂 `exit::tests::old_gate_budget_trips_on_next_attempt`（旧缺省 10 下
  紧随其后的第 16 条尝试被拒 = 变更**承重**）；登记条见 `docs/INTEROP-CRITERIA.md`
  （`per_src_fails` 缺省值变更条 + 「正常赛跑」措辞改写条 + `flood_refused`/`retry_sent` 输入集条）。
- **残余（交 S5 真机标定；如实登记，不粉饰）**：缺省 16 在 **pressure 档（缺省）+ 最悲观形态**
  （输家**永不完成**——用错 pin 建模）下 5 轮**仍会撞闸**（S4 实测：5 轮后 `flood_refused = 2`、
  `retry_sent = 8`、`handshake_failed = 8`），因为触发②（`RETRY_AFTER_FAILS = 5`）命中后每条
  「未完成」会**再叠一条重放尝试**（各计一次）；真岛形态（输家被 abort，但 quinn 驱动仍可能把手握
  走完 ⇒ 出口侧销账）介于两个模型之间。⇒ 16 是**「待真机标定」的初值**；且**触发②的 5 与 16 的
  预算不同步**（S5 已由 N4 复现，见 §1.5/§1.7）。

### 1.2 设计 §14-1④ 的如实回报：出口侧**能**区分「对端主动关闭」与「对端静默」（部分档位写清原因）

- **能区分**（以 quinn `ConnectionError` 变体为据）：`ConnectionClosed`/`ApplicationClosed` =
  收到对端关闭帧（含 TLS alert 类 crypto 错误）；`TimedOut` = 静默到 idle 超时；出口自己的握手
  期限 = `HandshakeOutcome::Deadline`（单列 `handshake_timeouts`）。
  **代码证据**（S4 新增，additive）：`ExitQuicSnapshot::handshake_peer_closed`（`handshake_failed`
  的**子集**；**只归因、不放宽**每源闸/证明失败闸的输入集）+ 用例
  `race_abort_form_stays_within_gate_budget`（错 pin 中止 ⇒ `handshake_peer_closed ≥ 8`）与
  `rpk_pin_mismatch_aborts_handshake`（≥1）。
- **不能区分的档位（写清原因）**：`TransportError` 一档既可能来自「对端发了坏帧」也可能来自
  「本地 TLS 栈因对端 alert 报错」⇒ 从变体**无法**反推对端是否发过帧；该档统一归「非主动关闭」。
- **客户端侧「显式优雅关闭」做不到（低成本的边界，按「别硬做」收口）**：`quinn::Connecting`
  **没有** `close()`（quinn 0.11.12：`Connecting{conn, connected, handshake_data_ready}`，无
  Drop-close）⇒ **未完成**的输家只能 `drop`/abort —— 那**只是停止等待**，连接驱动继续跑
  （S4 回环实测：3 候选 abort 后出口侧仍见到 **2 条完成**）；**已建立但未胜出**的输家仍走显式
  `close()`（`client/race.rs` 的 drain 循环，语义未变）。⇒ `client/race.rs` 模块头的旧口径
  （「输家 drop = 主动关闭」）**已按实测订正**（零行为改动，仅注释）。

### 1.4 【S6 新增·高危】D1：出口双栈 socket ⇒ 每源闸键恒为 `::/64`（**已修**）

- **现象（S5 实测，`M2-S5-evidence.md` §3.3/§4-D1）**：出口 QUIC socket 是**双栈**
  （`bind_dual_stack` 绑 `[::]`；E-q1 行 `quic: 端点就绪（[::]:42653…）`）⇒ IPv4 对端在 socket 面
  以 **v4-mapped**（`::ffff:a.b.c.d`）出现；`SrcKey::of` 只分 `IpAddr::V4/V6` ⇒ 键恒为 `V6([0;8])`
  （行文 `"::/64"`）⇒ **所有 IPv4 源共用一个桶**（设计 §3.2-④ 的「v4 /32」在双栈出口上**不生效**）。
- **读数（S5 §3.3 B3 臂，缺省 pressure 档）**：源 A（`192.168.3.12`）`flood pin-fail k=10`
  ⇒ `refused=0 transport=10`；紧接着源 B（`127.0.0.1`，异 /32）`k=8` ⇒ **`refused=8 transport=0`**；
  E2 臂：洪泛后**立即重连被拒**（`the server refused to accept a new connection`），等 11s 窗清后
  重连成功。行证：两条拒绝行的键**完全相同**（`握手洪泛拒绝（"::/64" …）`）。
- **修法（采纳 S5 建议）**：`SrcKey::of` 把 v4-mapped（`Ipv6Addr::to_ipv4_mapped()`，定义域 =
  RFC 4291 的 `::ffff:0:0/96`）归一为 `V4(a.b.c.d/32)`；其余 IPv6（`::1`/ULA/GUA/link-local）保持
  `/64` 聚合。新增单测 `exit::admit::tests::v4_mapped_sources_get_independent_v4_buckets`
  （异源独立计桶 + 与 v4 形态同键 + 真 IPv6 不归一 + 行为面「源 A 打满后源 B 仍放行」）。
  **判据行零变化**（`text()` 只是拿到归一后的键）。
- **修复前后对比读数**（同注入形态；出口 `HOMEWAY_QUIC_ADMIT_RETRY=never`，`F=16`/`W=10s`；
  「前」= HEAD `0d84673` 构建的二进制，「后」= 同树 + `ad03631`；原始读数落 `/tmp/d1-verify/`）：

  | 注入 | 修复前 | 修复后 |
  |---|---|---|
  | 源 A（`192.168.3.12`）`flood pin-fail k=20` | `flood: k=20 refused=4 transport=16 connected=0 timeout=0 total_ms=16` | `flood: k=20 refused=4 transport=16 connected=0 timeout=0 total_ms=14`（A 自身不变） |
  | 源 B（`127.0.0.1`，异 /32）常态准入 `conn` | `probe: 握手失败（RPK 钉定/网络）: aborted by peer: the server refused to accept a new connection` | `握手完成：1.5ms（127.0.0.1:42659）` + `准入: A4 收到（四帧走通；绑定已建立）` |
  | 源 B `flood pin-fail k=8` | `flood: k=8 refused=8 transport=0 connected=0 timeout=0 total_ms=1` | `flood: k=8 refused=0 transport=8 connected=0 timeout=0 total_ms=4` |
  | 出口行（键） | `quic: 握手洪泛拒绝（"::/64" 在 10s 内第 17 次尝试——已拒；第 1 次）` | `quic: 握手洪泛拒绝（"192.168.3.12/32" 在 10s 内第 17 次尝试——已拒；第 1 次）` + `quic: 连接采纳 … ← [::ffff:127.0.0.1]:63262` |

- **不回归（既有洪泛用例形态，照 S5 §3.1 B1 + §3.3 E2；修复后二进制实测）**：
  `flood pin-fail k=24` ⇒ `refused=8 transport=16`（= S5 B1 的 `refused=8=K−F` 逐位同）；
  同一源打满后**立即** `conn` ⇒ 仍被拒（有界性不变）；等 11s 窗清 ⇒ `握手完成：2.0ms` + `A4`。
- **归属**：S5 发现（高危面）→ **S6 整改**（commit `ad03631`）。**同类面自查**：
  `exit/socket.rs` 的 `LegTable` 与 `core/src/server/bind.rs` 的腿表以**同一进程内同一
  `SocketAddr` 值**为键（收发同源；腿 socket 按远端族建）⇒ 是标识符而非策略键，无需归一；
  `conn.rs::src_allowed` 比的是**内层 IPv4 头**与 `tunnel_ip/tun_ip`（无跨面地址比较）；
  客户端 `relay_sock.rs` 绑 `0.0.0.0:0`（恒 v4）。**range 外的同类缺口**见 §2.5-G3（登记豁免）。

（闸上限：第 17 次起拒绝）**是两级不同的决策**，构成**单调升级**：先加压（Retry 提高攻击者
一次性成本），后拒绝（闸切断）。二者**不同步是设计意图**：
- 5 是「开始不信任」的**早期信号**（阈值低 ⇒ 早施压），16 是「已经过载」的**硬界**（阈值高
  ⇒ 不误伤正常赛跑包络）。若把 5 抬到 16，则 Retry 只在闸即将拒绝时才启用 ⇒ 压力面失去
  「先于拒绝生效」的价值（攻击者可在无 Retry 成本下把预算用到 16）。
- 代价（S5 B2 实测，如实）：pressure 档最悲观形态下，客户端第 11 次尝试即被拒（每条未完成
  尝试在触发②后**再叠一条**重放尝试，各计一次闸预算）⇒ **客户端可见预算 ≈ 16/2 = 8–11 次**。
  该形态是「输家永不完成」的建模，真岛形态介于两模型之间；真机标定归 S5-4/真机批。
