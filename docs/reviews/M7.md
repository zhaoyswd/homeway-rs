### 3.1 S1 旧 token 归因行（M6 `§12-1` 交下；设计 §10-5）

**问题**：设备核换代后，App 主机卡里存的是旧 `hmw1` token ⇒ 新版核报
`homeway/token: 不支持的 token 版本: hmw1`——这是「换代的必然结果」，但**没有可行动指向**
（用户不知道要去哪取新串，容易误判为「串坏了」）。

**落点（按设计「客户端 token 解析错误面」）**：

| 层 | 改动 | 语义 |
|---|---|---|
| `crates/homeway-core/src/token.rs` | 新增 `TokenError::changeover_attribution()`（只有 `UnsupportedVersion` 返回归因，`Corrupted`/`Malformed` = `None`）+ `user_message()`（= 哨兵 `Display` + 归因） | **哨兵字节零改**（`fixtures/vectors/token_hmw2.json` 的 `sentinels` 仍逐字钉住 / Go 对齐面不动）；本条只做**追加** |
| `crates/homeway-core/src/facade/tun_exec.rs`（`warmup`） | `token 解析失败：{e.user_message()}` | **App 用户可见面**（`tunStatusJSON` 的 `failed` reason）——设备换代后的主路径 |
| `crates/homeway-core/src/facade/service_exec.rs` | 同上（服务会话域 reason） | 服务域同口径 |
| `crates/homeway-cli/src/main.rs` | 新增 `token_or_exit(s, prefix)`，7 处 token 解析点（`token` 三处 / `connect` / `speedtest` / `files` / `portfwd`）统一走它 | CLI 面（排障期用） |
| `crates/homeway-cli/src/daemon_cli.rs`（`host add`） | 本地语法校验失败文案走 `user_message()` | 「添加主机」自助面 |

**归因文案（逐字）**：`存量 token 已失效（WG→QUIC 换代：本代只铸/只认 hmw2）——请重新向出口索取
token（`homeway-cli serve token`）后重新粘贴`。

**用例**：
- 单测 `token::tests::unsupported_version_carries_actionable_changeover_attribution`：`hmw1` 串 ⇒ 归因含
  「存量 token 已失效」+「hmw2」+「serve token」；`user_message()` **以哨兵原文开头**（前缀段不可改）；
  真坏串（`Corrupted`/`Malformed`）**无**归因且文案 = `Display`（防误归因）。
- e2e 负向 `crates/homeway-core/tests/quic_wg_e2e.rs::legacy_hmw1_token_surfaces_actionable_changeover_attribution`
  （**常跑**，无需出口）：`hmw1` 串进 `tun_prepare` ⇒ `failed` 终态 + reason 同时含哨兵原文与归因 +
  **不得**出现「校验失败」话术 + 单飞锁已放（下一次 prepare 可受理）。
- 脚本面 `tools/quic-wg-e2e.sh` 新增：①`run_one` 跑上述用例并进 SUMMARY；②**CLI 面断言**
  （`host add hmw1…` ⇒ rc=1 且 stderr 含哨兵 + 归因四段；本地语法校验前置 ⇒ 不连 daemon、不入表、零副作用）。

**出口侧「why 字段」= 判定不必要（如实登记）**：出口在 wire 上**拿不到 token 版本**——设备侧在
**本地**解析 token（版本面即拒）；即便旧核发起连接，新出口也只看到「非 QUIC 的 UDP 载荷」，
无从归因到 token 代际。⇒ 按设计原文「**必要时**」，本棒**不动**出口侧准入行。

**真机面**：归 **U2**（设备核换代窗口）。真机实录判据 = 注入旧 token 后 App/状态面出现上述归因
（`tunStatusJSON` reason 或 CLI stderr）。
