# 公网观测腿 r5 全项整改（2026-10-21）

入口：[原评审](2026-10-21-公网观测腿评审.md)，基线 `c8f56be`。本轮按用户“修正所有问题”处理原评审四项缺陷及相邻观察项；不升级协议、不修改客户端恢复策略、不部署生产出口。

## 技术门与实现约束

开工前分别完成 DoH、引擎、中继的技术设计与结构化自评；实现后完成代码自评，再由独立子任务交叉复核生命周期。原始记录在 [implementation-review.md](2026-10-21-public-endpoint/implementation-review.md)。本轮未主动启动新的 dsh 外评（reviewer skill 限制为用户明确要求评审时触发）；原评审的 dsh 原文完整保留。

本轮把不变量放在其真正所属的层：TCP 每次底层 IO 都检查绝对期限；cache/token 提交与世代停止共享发布门；持公共端口 fd 的线程必须有 owner 并等待退出。没有用多加几个原子 load 代替事务或线程收尾。

## 逐项处置

## 独立复核后追加修正

1. **并发 stop/shutdown 二次调用提前返回**：最初 take 句柄再解锁 join，会让第二调用将“空句柄”错认成“已完成”。现外部 stop 持 observers 锁直到 join 完成，shutdown 另有 completion 门；并发测试确认两个外部调用均等待。
2. **观察日志重入形成 join 环**：保存不可变观察线程 ID；观察回调内 stop/shutdown 只请求停止、不等锁或自己，外部 shutdown 返回才代表完整收尾。回归将真实 pubep logger 暂停，两个外部调用等待，同时回调重入 stop/shutdown，最后确认端口可重绑。
3. **UPnP hostname 兼容性回归**：最初所有 hostname 都回用 SSDP 源会错投异主机 controlURL，公开 localhost helper 也会失败。已限定来源地址只绑定原 hostname，其余使用有界共享解析；localhost 和“来源为不可达地址、control hostname 为 localhost”的真实 HTTP 回归均通过。
4. **隔离门与前批同步 DoH 不一致**：原门将 rustls 一律当作异步依赖，前批 `rustls.workspace=true` 已使门红；其异步 panic 回归又用了 std::thread::sleep。后者改 tokio sleep；前者登记同步 TLS 的单文件例外，只允许 core 的精确依赖和 server/doh.rs 消费。增加所有同步 Rust 文件反向扫描，仍禁止 quinn/tokio/async fn/async 块/await；自校准覆盖例外、异文件 rustls、async 块与普通 await_quota 方法。不是开放 runtime 或跳过 TLS 证书验证。

以上均已修正，独立记录中的旧 P2/P3 以这里的最终处置为准。没有未处置的已确认代码缺陷。

### 验证边界

TCP connect_timeout 是一次有界调用，取消可能等待剩余连接预算，单次不超过 3s。getaddrinfo 本身不可取消，但最多一个进程级解析 worker、一个排队项，不持有出口、发布权或公共监听 socket；外部等待按期返回。观察回调内停机只有请求语义，完整完成由外部调用确认。默认供应商可用性和 Windows 真实钉卡验证保留原登记，不伪造本次运行证据。
