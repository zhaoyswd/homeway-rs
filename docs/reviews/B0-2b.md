## 一、并发模型拍板（任务书点名的评审项）

**结论：沿 R1 决议「自管线程 + 独占 fd」，不引入新模型（tokio/async/全局 reactor
均不引）。** control 面 = 每连接三线程（reader / dispatcher 工位 / writer 唯一写者
+ Condvar 优先级出队）+ 每流两线程（下行泵 / 上行泵）；与 R3 出口的「一条 WG 驱动
线程 + 固定 worker 池」同族——控制面连接数与流数天然有界（连接 = CLI 短命 + 少量
前端；流 ≤ 8/连接、上行工位总量 ≤ 64），无 poll(2) 多路复用的密度需求（每 fd 一条
阻塞 reader 是最简且足够的形态；epoll 化在无 tokio 约束下只有手写 reactor 一种路，
复杂度不成比例）。与 Go 的差异全部收敛在「Go goroutine channel 语义 → Rust 单写者
复合出队」一处（见 §二 B3 条），wire 行为逐条对齐（见 §四测试）。

## 九、第 2 棒判据实测（本地实例：daemon = /tmp/hw-2b2-uni、exit = local-rust-exit #1

### term `--host` 远程全流程（9/9，PTY 驱动 = 每腿独立伪终端 + 键序喂入）

- 新建+回显：`term new pty-xxx` → ATTACHED/REPLAY-DONE → 回放前序 + `echo T1-ECHO-LIVE`
  回显到达；
- **命令真执行**：`touch /tmp/hw-term-marker-<rand>` 经隧道在**出口侧 shell** 执行
  （marker 落盘核对）；出口日志 `term: 新建会话 pty-…（pid=… 80x24 shell=/bin/zsh）`
  + `腿接入（kind=host … id=host-… 首腿=true）n=1/8`；
- exit 自灭：`exit 7` → CLI 收 `会话 … 已结束（退出码 7）`（ENDED code 直传）；
- KILL：另一 CLI `term delete` → `会话 … 已结束`（delete 方）+ 在接腿
  `会话 … 已被关闭（App 或 homeway-cli term delete）`（ENDED -2）；
- 接管：第二腿 `attach -d` → 首腿 `会话 … 已被另一客户端接管（replaced）；重新
  接入：homeway-cli term attach …`（ENDED -1/replaced）；出口 `腿断开（原因=takeover）`；
- 分离键：Ctrl-b d → `已分离（会话 … 继续在出口运行）` exit 0；
- 本地面（直连 term.sock）同套 9/9；
- 非交互面：远程 list（空/表格/JSON 字段与出口 LIST 同构）、new -d、explain 在线
