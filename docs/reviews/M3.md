## 2. S5 准入失败归因回传（§4）

### 2.1 出口关闭码表与落点

- **码表单源** = `crates/homeway-quic/src/admit_close.rs`（新增，纯 std）：
  `0x11 凭证不被接受` / `0x12 资源暂不可用（稍后重试）` / `0x13 准入数据非法` / `0x14 准入超时`。
- **带码点**（准入窗内三处，§4 的「4 + 3」表）：`exit/conn.rs::reject()`（MAC 不符/证明失败闸
  ⇒ `0x11`；引擎裁决按桶；帧格式/版本族 ⇒ `0x13`）、`time_out()`（两族计时器 ⇒ `0x14`）、
  `ask_engine` 入境队列满（⇒ `0x12`）；**准入后**的会话级关闭（`unbind_pub` 的 `device removed`、
  `bind` 的 replaced）与刷新面拒绝留 `0`（`CloseCode::Session`）。
- **引擎裁决的类**跨 crate 带回：`RejectWhy::EngineRejected` 由单元变体改为携带
  `EngineRejectClass{Credential,Resource}`；映射单源 =
  `homeway-core::server::table::RejectReason::engine_class()`
  （`no-token`/`revoked` ⇒ 凭证桶；`table-full`/`ip-conflict` ⇒ 资源桶）。
- **出口侧详细归因行（`quic: 准入被拒（dev=…`）与计数集逐字不变**（§4 的安全面：不发新帧、
  不改状态机、不放宽任何闸）。

### 2.2 客户端映射与观测面

- `IslandErr::AdmissionRejected{code}`（**只在未绑定态**映射；白名单外/无关闭原因仍
  `RegistrationFailed`）与 `IslandErr::SessionClosed{reason}`（准入后的独立分支）——分界写死

## 3. 偏离设计（逐条 + 原因）

1. **QUIC 档连接面失败不注入 WG 恢复阶梯**（设计 §1.6 写「只有 `{Closed,Timeout,EngineGone}`
   触发恢复」）。**原因**：§3.4 明令「QUIC 档不再产生 C11 族行」，而现有 `run.recover_until`
   的动作面全在 WG（`rebase/rearm/reset_peer_session`）——QUIC 档调它 = 既产生 C11 族行又做无效
   动作。**本切片取**：连接面失败在调用方预算内**重试一次**（`dial_with`），QUIC 档的恢复动作
   整体归 S4 的阶梯重写。**影响面**：QUIC 档服务流拨号的失败路径（可观测面 = 既有 C19 族行 +
   新增 `quic: 服务流重试（tag=%s；首试 %s；余预算内再试一次）`）。
2. **§5.1 第 5/6 项（`files.rs:207`、`service_exec.rs:577`）在 M3 不适用**。**事实**：
   `files.rs` 的动词面只被 CLI 本地形态消费（`homeway-cli` 的 files 命令 + `Session` 拨号
   = WG 承载）；`service_exec.rs` 是「服务会话」域（`ClientCoreServiceStart` 自陈
   「App 进程内、无 TUN 的 WG 会话 + 三座桥」）——**该域没有岛**（岛的构造点 = 隧道域，§2.6）。
   App 核的服务流实际走**隧道域**的桥，已换轨（§1.2 的 `[e2e5]`）。**影响面**：设计 §5.1 表的
   第 5/6 行需 S6/S7 按此订正（不是漏做）。
3. **`quic` 段存在判据放宽**：从「quic 档 **且 L3 落在岛上**」改为「quic 档 **且岛已构造**」。
   **原因**：岛建连失败（含准入被拒）时本世代回落 WG——旧判据下该段整段缺席，§4 要求的
   「App 可见为什么走了 WG」不可达（M2 真机发现①的黑洞面）。**影响面**：`tunStatusJSON` 读者
   （additive 键 + 段落出现面变化）⇒ S7 登记。
4. **A13 的 `facade/term_op.rs` 文案不改**（「出口 7724 端口上不是终端服务」）：它是 Go 真源
   （`baseline:app_term.go:125`）的 App 可见文本，改字会脱钩基础词表；且该处端口是「服务身份」
   指代而非拨号目标。代码内已写明登记（如需去端口 = 跨仓词表批）。
5. **QUIC 档未知虚拟端口 ⇒ `Unsupported` 错**（不回落 WG）：静默回落会把「QUIC 档零 stackb」
   变成条件成立；三个服务端口全在映射内 ⇒ 生产面不可达。

### ① `T_recv ≤ 3.5s`（kill -9 两相位；起点 = E1 `serve 就绪` 行时刻）


## 3. 偏离设计（逐条 + 原因）

1. **阶梯落在岛内（`client/ladder.rs`）而不是世代层**。设计 §3.1 只写「沿用 `quic_heal` 的
   swap 单飞位」；但 §3.2-1 点名「拍间 ≤300ms **由 runtime 拍内务驱动**」，且 M/R 的判据信号
   （`SockStats` 发送面错误）与动作（`Face::rebind` / `client::connect`）**全在岛内**。
   **取**：阶梯整体在岛内 ⇒ 单飞改为**结构性**（`Ladder::inflight`/`pending`），世代层的
   `quic_heal` 位随 M1 动作面一并删除（不残留第二真相面）。世代层只剩 **B** 的接收端
   （`quic_unhealthy_signal` ⇒ 如实判不健康 ⇒ 既有扩展重建）。
2. **阶梯只在 TUN 在位后跑**（`st.tun.is_some()` 门槛）。§3.2 的两档都把 `attached` 写成前提
   （「在用档 = 有需求」「待机档 = **attached** 无需求」），且未附加期无数据面要保；
   另一条硬理由 = N14 的容量用例：探活持久流会占一条 quinn 信用，未附加时开它会与
   「服务流容量 = 上限 − 2」的标定用例冲突。未附加期的死链由世代层 60s 巡检兜底
   （既有 `mark_unhealthy` 3 连败支路，本切片保留为保险丝）。
3. **链路确定性死亡（`close_reason` 非空 / 刷新写失败）不吃探活预算**，直接进动作判别。
   复探（§3.1-1）的语义是**假阳性抑制**（路径抖动），而确定性死亡不是抖动（协议层已定音）；
   活性不放松（`fail_step` 只回 M/R/B，绝不回 `Probe`）。**影响面**：`T_detect` 的
   「两次瞬时失败」形态（可观测面同面，无判据行差异）。
4. **负向②的注入形态**：设计写「回显任务挂起但连接活」——产品侧挂不起来（那是出口代码，
   且给产品加注入旋钮违 M0 纪律），故用**外向丢包**（`tools/quic-wedge-proxy.py`）复刻
   客户端可见的同一谓词：无回显 + `close_reason()` 空 + `connections=1`（用例三条都断言）。
   **影响面**：该用例的故障形态是「黑障」而非「应用层挂起」——对阶梯而言不可区分。
5. **M 的确认探活也走「另一动作」链**：设计 §3.1-3 只写「动作失败 ⇒ 另一动作（M↔R）」；
   本实现把 **M 的确认探活失败**也算作 M 失败（⇒ 置 `migration_unconfirmed` + 立即 R），
   与 §3.1 末段「Rebind 后一个预算内无回显 ⇒ 置位 ⇒ 允许走 R」同源（相位 B 实测正是这条链）。
6. **既有 `[e2e4]` 的 E-q5 断言按节流口径对齐**（受理**或**结束）——S4 新增的 probe 流占掉

#### 3.2 QUIC 档：快探 → 复探 → 迁移/重连 → 世代重建（现行）

| 动作 | 触发（**显式信号**，不用「udp_rx 停增」推断） | 做什么 | 判据行 |
|---|---|---|---|
| **M 迁移** | 快探**复探失败** 且本机发送面**有**错（errno ∈ {ENETUNREACH, EHOSTUNREACH, EADDRNOTAVAIL, ENETDOWN, EINVAL}，新鲜窗 5s；`WouldBlock` **不算**错） | 换本地 socket，保连接；随后快探确认 | `quic: 本地 socket 已换绑（from → to）—— M 动作（原因=…）`；确认成功 `quic: 迁移完成（from → to，耗时 …）`；一个探活预算内无回显 ⇒ `quic: 迁移未确认（…）` |
| **R 重连** | 快探**复探失败** 且本机发送面**无**错（对端不可达/进程死） | 新 QUIC 连接（同端点、同本地 socket）+ 四帧准入；服务流**按需重开** | `quic: 链路重连中（原因=…，第 N 次）` → `quic: 链路重连完成（原因=…，耗时 …）`；败 `… 链路重连失败（…）—— 交世代重建` |
| **B 世代重建** | 连续 **2** 次 R 失败 **且** 累计失败窗 **≥10s** | 既有 `rebuild_session`（重赛跑/换候选/换 token 端点；赛跑失败 ⇒ 回落 WG 承载） | `quic: 世代重建（原因=…；连续重连失败 N）` + `unhealthyReason=patrol`（值域不变） |

**动作顺序（写死）**：① 快探失败 ⇒ **不动连接**，本拍内**加倍预算复探**（700ms → 1.4s）；
② 复探成功 ⇒ 判**路径抖动**（记行 + 计数；连续 3 次 ⇒ 升格为失败，防 fail-silent）；
③ 复探失败 ⇒ 按上表选 M/R；动作后快探确认，败 ⇒ 另一动作（M↔R）；④ 两动作都败 ⇒ 计入 B 门；
⑤ **复探两次之后必有动作**（活性：不得无限静默）。
**动作单飞**：并发信号合并（岛内结构性单飞，不重复动作）。

**快探节拍**：在用档（有出站需求，新鲜窗 5s）首探预算 **700ms**、拍间 250ms（背靠背）；
待机档（attached 无需求）**60s**（= 原巡检节拍，保电池/CPU）；挂起空窗（>2×60s）⇒ 立即探。
**载体**：一条常驻 `STREAM[probe]`（写 1B 等 1B 回显）——**应用层回显是唯一能在 1s 内定音的判据**
（纯连接面要等 `max_idle_timeout` 30s + keep_alive 相位，实测 40.0s）。
**明确排除的判据**：ICMP 端口不可达（UDP 为**非 connect** 抽象 socket）；`udp_rx` 停增（不可判定）。

**判据行族（QUIC 档恢复时间线；与 `RECOVER` 族是**替代**关系）**：
`quic: 链路快探失败（连续 %d，原因=%s）` / `quic: 链路探活抖动（%s，已复探）` /
`quic: 连续 %d 次抖动升格 —— 计入失败链（防 fail-silent）` /
`quic: 链路动作选 M（换本地 socket）|R（新 QUIC 连接）（原因=…；…）` /
`quic: 交另一动作（M↔R；窗 %v / 门 %d 次未到）` /
`quic: 链路重连中（原因=%s，第 %d 次）` / `quic: 链路重连完成（原因=%s，耗时 %v）` /
`quic: 链路重连失败（原因=%s，第 %d 次）—— 交世代重建` / `quic: 世代重建（原因=%s；连续重连失败 %d）`。

#### 3.3 「出口重启自愈 ≤3.5s」的门槛与计时（可 falsify）

- **门槛量 `T_recv ≤ 3.5s`**：起点 = 出口**重新监听**（既有判据行 `serve 就绪` 的时刻）→
  客户端**首个回显成功**。（**不得**用 harness 拉起进程的时刻当起点——会系统性漏算启动时间。）
- 两段独立量：`T_detect` = 首探 700ms + 复探 1.4s + 拍相位 ≤250ms（**实测 2514 / 2520ms**）；
  动作（M/R）+ 准入 + 首回显 **实测 ≈0.3s 内**（回环：握手 2.7ms / 首个流回显 0.2ms；`heal` 台
  「重启 → 重连完成」268ms）。
- **本机实测（kill -9 两相位，起点 = 出口重新监听）**：`T_recv = 2455ms`（停机 < T_detect）/
  `1315ms`（停机 5s）。**旧路径对照**：40.03s（QUIC 空闲回收 + keep_alive 相位，无流量连接）。
- **真机同时记 `T_total`**（出口不可达 → 恢复）：含出口启动/人工启停 ⇒ 大于 3.5s 属预期。

#### 3.4 与巡检 / 需求门控的接口（不变面）

- 60s 巡检节拍、需求门控（`patrolEvidenceGate`）、`unhealthyReason` 值域（`{patrol,fd,panic,stop}`）
  **对 WG 档逐字不变**；QUIC 档的巡检**只留痕**（动作面在岛内阶梯）——
  判据行 `quic: 巡检失败 —— 动作面在岛内快探阶梯（§3.1；本拍不重复动作）`；
- **QUIC 档的环境噪声位**：**不读** WG 腿的本地发送错误（分档纪律），改由岛侧「发送面错误计数」
  （非 `WouldBlock` + errno 白名单 + 5s 新鲜窗 + 换绑清零）承担；
  `patrol` 分类在 QUIC 档的触发源 = **B 门之后**（连续 2 次 R 失败 + 窗 ≥10s）。
