stage/backup 路径，以及 root 当轮重新核实的旧 PID/SHA/版本。云 smoke 的 helper SHA

## Root 执行顺序与恢复边界

先完整本地门、push/main CI、main 头 tag、五平台官方 Release 成功。本机统一下载到
`/tmp/homeway-v0.3.25-official/` 并校验同版 SHA256SUMS、架构、版本；Mac 不重签。
云件只从本机 scp 上传，远端再次核归档/二进制/SUMS/脚本 SHA，不由云直连 GitHub。

Mac 使用同官方件跑 `tools/tui-smoke.py --bin <official>/darwin-arm64/homeway`，按当前
手册可补 selection/remote smoke；工具均显式 `/tmp` 私有 state。云 stage 固定
`/tmp/homeway-v0.3.25-cloud-deploy-20261030-r1/`，root 上传 `homeway`、官方归档、
SHA256SUMS、`ali-deploy.py`、`cloud-smoke.py`，生成0600 `deployment.json`，先运行
`/usr/bin/python3 <stage>/cloud-smoke.py`。smoke 验证私有准入/路径探测和三轮共享 QUIC
LIST/surface/resize/KILL，收尾只清理由该私有 daemon 派生的进程，并比对正式 critical。

Mac 工件仅留存未来显式授权后使用，newhash/resume 仍可 null，不生成可 activation 状态。
未来本机获授权时，私有配置 source/archive/checksums 固定到官方目录，new_sha/
archive_sha256 填实际值；resume_file 只写本机私有恢复指引，不上传云，不进公开仓。
以下命令仅登记未来步骤，**本轮禁止执行**，届时还须重新 fresh 核对旧 PID/SHA：

```sh
/opt/homebrew/opt/python@3.13/bin/python3.13 /tmp/homeway-v0.3.25-release-deploy-20261030-r1/deploy.py prepare --config <root私有JSON>
/bin/launchctl bootstrap gui/501 /Users/zhaozhe/homeway-rollback/release-v0.3.25-20261030-r1/once.plist
```

云模板填官方真实 hash，原 critical/starttime 保留，由 root 在远端生成同目录配置：

```sh
/usr/bin/python3 /tmp/homeway-v0.3.25-cloud-deploy-20261030-r1/ali-deploy.py prepare
/usr/bin/python3 /root/homeway-rollback/release-v0.3.25-20261030-r1/ali-deploy.py activate
```

本轮仅云 prepare，须实际 exit0，持久 receipt 为 PREPARED/activation_started=false 后
唯一激活并独立 SSH 核验；本机不 prepare、不激活。工件中各机持久备份位置为
`~/homeway-rollback/release-v0.3.25-20261030-r1/`，包含旧件、state 备份、manifest、
receipt 与恢复工件；state 不自动覆盖恢复。断线后先读 receipt 并确认 worker 状态，
不要重复 activation；必要恢复按该目录 RECOVERY/rollback 指引执行。最终验收必须
实核官方 SHA/准确版本、唯一零参进程和运行映像、原角色/端口、原身份/config/台账前缀、
被动终端能力与稳定窗结果，不能只看 activate 命令返回。
