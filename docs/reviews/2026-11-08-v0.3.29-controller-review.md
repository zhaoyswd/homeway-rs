## 2. 问题清单

### P1｜高｜条件阻塞：既有 `enabled=true` Web 配置没有前置拒绝，bootstrap 可抢先启动并导致回退卡死

**文件:行**
- `web_deploy.py:77-90`（prepare 接受任意既有配置）
- `web_deploy.py:92-94`（assert_before）
- `web_deploy.py:286-289`（initialize 先 assert，后写 web-intent）
- `web_deploy.py:317-324`（rollback 无 intent 时 assert_before）
- `deploy.py:769-777`（replace → unload → bootstrap → initialize）
- 产品侧：`crates/homeway-cli/src/webserve/host.rs:127-131`、`222-246`

**问题**
1. `web_deploy.prepare` 只记录/备份既有 `webserve.toml`，不拒绝 `enabled=true`。
2. 新 v0.3.29 daemon 启动时 `Host::bootstrap` 会读取 `enabled=true` 并自动 `webserve.start`，发生在 worker 的 `web_helper.initialize` 之前。
3. 若旧配置端口/origin 与固定计划不同，`initialize` 的 `start` 会报“已运行且配置不同”；若 bootstrap 重写了 TOML 字节/元数据，`initialize` 的 `assert_before` 直接失败。
4. `web-intent.json` 是在 `assert_before` **之后**才写的；一旦 assert 失败，rollback 看到“无 intent”，又执行 `assert_before`，仍失败。`do_rollback` 在 `replace_binary` 之前调用 web rollback，因此会留下：**新二进制已安装、原 job 已卸载、旧二进制未恢复、回退失败**。
5. 另外，既有配置若 owner 不是 UID501，`rollback` 只 `os.chown(-1, gid)`，不恢复 uid；`record` 包含 uid，最终在 `web_deploy.py:340` 失败，仍会在旧二进制恢复前中止。

**最小建议**
- 在 `web_deploy.prepare` 增加明确前置门：
  - 既有 `webserve.toml` 若 `enabled=true`，直接拒绝，除非另做完整、经测试的迁移方案；不要依赖“旧配置恰好等于固定计划”。
  - 拒绝 TOML 无法解析、未知字段、非 UID501 或 gid 不可恢复的配置。
  - 对既有 `web/auth.key` 同时校验 53 字节 `HWWK\x01`、0600、owner 可读。
- 或在 rollback 中显式处理“无 intent 但配置已被 bootstrap 修改”的已识别情形；但“拒绝 enabled=true”更小、更安全，不扩大支持面。
- 当前实际文件不存在，所以**本轮不触发**；但 root fresh 检查若发现任一文件出现，必须停止并按上述前置门处理。

**是否阻塞：** 当前运行不阻塞；**对“支持既有 Web 配置”及未来 prepare 条件阻塞**。

### P2｜高｜阻塞代码门：Web SUCCESS 收尾没有最终状态/配置/key 复验

**文件:行**
- `web_deploy.py:297`（只在 verify 前检查一次 `state/listen`）
- `web_deploy.py:301-313`（verify 后只轮询 `ui_count`）
- `deploy.py:777-780`（initialize 后的 `service` 不检查 WebServe）
- `deploy.py:685-708`（`service` 只检查 daemon 角色）

**问题**
- cleanup 循环只判断 `status.get('ui_count') == baseline`，不判断 `state == 'running'`、`listen == '127.0.0.1:18080'`。
- verify 完成后没有重新读取并比对 `webserve.toml` / `web/auth.key` 的最终记录。
- `worker` 随后只做 daemon `service`/critical，不覆盖 Web 是否仍运行、配置/key 是否漂移。

我在临时副本中独立模拟：最终 `status` 返回 `state=failed`、`listen=null`、`ui_count=0`（与 baseline 相同），`initialize` 仍正常返回成功证据。这意味着 webserve 在 25s 验证/5s 清理窗口内崩溃，控制器仍可能写入 `SUCCESS`。并发修改配置或 key 也可被漏过。

**最小建议**
- cleanup 循环条件改为同时要求：`state == 'running'`、`listen == '127.0.0.1:18080'`、`ui_count == baseline`。
- verify/cleanup 结束后再做一次最终读取：
  - `record(state/CONFIG) == web-written[CONFIG]`；
  - `record(state/KEY) == web-written[KEY]`；
  - 最终 status 再次满足 running/listen。
- 任一不满足即走 rollback，不得写 SUCCESS；补对应测试。

**是否阻塞：** **是，阻塞代码门。**

### P3｜高｜阻塞代码门：resize 之后的 exit/error/异常 close code 被忽略，仍可判 SUCCESS

**文件:行**
- `web_deploy.py:253-263`（首屏循环）
- `web_deploy.py:264-272`（resize 循环，一旦有任意 binary 就退出）
- `web_deploy.py:273-277`（close 循环只判断 opcode==8，丢弃 body）

**问题**
- 首屏只要求 `ready` 与 `主机` 子串，不要求完整屏幕；resize 只要求任意 binary 输出。
- 一旦 `resized_output` 非零，后续 text `{"type":"exit"}` / `{"type":"error"}` 不再检查。
- close 循环收到 opcode 8 即 break，不检查 close code；服务端在 TUI 退出/错误时可能先发 `exit` 文本再发 1000 或 1011 close。
- 因此“首屏出现后 TUI 立即退出/出错”仍可能返回 `ready=true` 的成功证据。

我在临时副本中独立模拟：序列为 `ready → 主机 → resize输出 → {"type":"exit"} → close 1011`，`verify` 仍返回成功证据。

**最小建议**
- close 循环中：
  - 若收到 text，解析并拒绝 `error`/`exit`；
  - 若收到 close，要求 body 长度至少 2 且 code 为 1000；异常 code 必须有界失败。
- 首屏判据至少等待完整首屏标志（如 TUI footer `h 主机  s 会话  Enter 终端`）或稳定窗口，不只看单个 `主机`。
- resize 后继续检查是否出现 error/exit，直到正常 close。
- 补“exit after resize”“close 1011”“close body 缺失/异常”测试。

**是否阻塞：** **是，阻塞代码门。**

### P5｜中高｜阻塞代码门：rollback 证据写失败会阻断旧二进制恢复

**文件:行**
- `web_deploy.py:345-346`（`web-rollback.json` 的最后写入）
- `deploy.py:728-731`（unload → web rollback → replace_binary）

**问题**
- `web_helper.rollback` 在配置恢复、key 检查之后调用 `save(web-rollback.json)`；若该写入/fsync 失败，异常直接传回 `do_rollback`。
- `do_rollback` 尚未执行 `replace_binary(staged_old, old_sha)`，也尚未恢复原 plist/bootstrap。
- 结果是：**新二进制仍在 PATH，原 job 已卸载，旧二进制未恢复**，同时 receipt 只能写 `ROLLBACK_FAILED`。
- 这是证据写入失败导致生产恢复失败，不符合“回退 180s 独立完成”的目标。磁盘空间、权限或目录 I/O 异常都可能触发。

**最小建议**
- 将 `web-rollback.json` 作为**best-effort 证据**：写入失败只记录警告，不阻断后续旧二进制/plist 恢复。
- 或将 rollback 拆成“状态恢复”和“证据落盘”两阶段，证据失败不得改变恢复流程。
- 对 `sync_dir`/`save` 的失败边界单独测试；至少补“web rollback 证据写失败仍恢复旧件”的 mock。

**是否阻塞：** **是，阻塞代码门。**
