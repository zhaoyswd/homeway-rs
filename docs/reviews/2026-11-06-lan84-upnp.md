为 Wi-Fi，`.84/en7` 为同一机器的外接网卡。本轮不操作本机或阿里云出口的部署；

## 结论一：规范 LaunchAgent 可以恢复正式程序的权限归属

旧 PID62778 为 SSH 拉起后脱离的裸守护，PPID1 不代表 launchd 托管。
`launchctl procinfo` 显示其 `responsible path=/usr/libexec/sshd-keygen-wrapper`；
SSDP 发送长期报 `No route to host (65)`。

最初临时诊断程序在 SSH 会话存活时成功；后台或普通用户 launchd 形态下，
Rust SSDP 报错误65，Network.framework 返回 `localNetworkDenied`，uid0 对照成功。
**这些临时程序与
homeway 的签名身份不同，不能据此断言正式 homeway 的普通用户 LaunchAgent
也不可用。** 前期这一过宽归纳已在同件实测后明确纠正。

正式同件 SSH 对照 PID3721 可以发现 IGD；退出后先恢复裸守护 PID3781 并核验
身份、配置、台账前缀、控制面和 UDP38242。再以临时 LaunchAgent 启动正式同件
PID3886，SSH 退出后仍可发现路由器，其 `responsible path` 已变回
`/usr/local/bin/homeway`；22:15 自然周期仍能发现 IGD。
因此无需让正式 homeway 长期以 root 运行，也未引入私有责任归属 API。

## 结论二：UPnP 控制请求源地址与 InternalClient 不一致触发 402

路由器为华为 Q7（MEDUSA2-BR80-10），IGD 控制服务为 WANPPPConnection:1。
它自报 `Connected`、`PPPoE_Bridged`，外网地址为空；这些字段不能单独用来
断言它不能映射，因为受控 AddPortMapping 随后已成功。

同件 SSH、LaunchAgent 均发现 IGD 后，原生 AddPortMapping 返回 402，
AddAnyPortMapping 返回 401。路由器 SCPD 的参数名与程序发送参数一致。
本轮 SSDP 收集只收到一处 IGD，没有证据支持“改选另一个 WAN 服务”作为本次解法。

受控试验仅使用预先确认未占用的外部 UDP43842、内部 UDP38242、独立描述，
参数采用空 RemoteHost、3600 秒租期。每次前后完整枚举所有 RemoteHost 条目，
精确核对描述、IP、内外端口和协议后删除；所有测试映射均已回收。

| HTTP 请求源 | NewInternalClient | 路由器结果 | 外网探针 |
|---|---|---|---|
| .71 / en0 | .71 | 200，规则存在 | 回包源 114.242.60.128:43842，44ms、92ms |
| .84 / en7 | .71 | 402，无规则 | 不进行规则成功推断 |
| .84 / en7 | .84 | 200，规则存在 | 收到 nonce 回包，但源端口为38242而非43842 |

最后一项时 QUIC 仍绑 en0；该异源端口回包不能等同于完整 QUIC 建连成功，
说明还必须保持映射目标与传输实际出口一致。以上只验证参照点探测，未宣称
完整 host add、注册或终端服务已在这些临时映射上通过。

源代码中 `discover_igd_context` 用本地候选完成 SSDP，但后续 HTTP 连接没有
绑定该本地地址；候选首项为 .71，系统到路由器的默认 TCP 源为 .84。
PID3886 的限定抓包直接捕获了发往 IGD 的 POST：源 .84/en7。该抓包未包含
完整 NewInternalClient，目标 .71 的归因来自代码路径与上表受控交叉对照，
不能把抓包未得到的字段说成已直接捕获。

## 后续代码修复范围

1. 让 IGD 描述读取、映射表查询、Add/Delete 与租期维护的 HTTP 连接携带并
   使用所选本地 IPv4/接口，避免 SSDP 与 SOAP 分别选路。
2. UPnP 候选选择需与 QUIC 运行期绑定接口协调；换卡触发后重建正确映射，
   不能只将候选按枚举顺序任取首个。
3. 回归应覆盖双网卡源地址/映射目标组合，外网验证还须检查返回端点，不能
   仅凭 200、STUN 同端口或 nonce 应答宣称完整数据面可用。

本轮仅排查并修正启动托管方式，不修改产品代码，不发新版本。
自动 UPnP 的双网卡缺陷仍需后续实现和发布。
