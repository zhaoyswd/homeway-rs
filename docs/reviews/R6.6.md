## 一、评审结论摘要（原样要点）

- **高危：无。** 三条硬不变量（cwnd 上界闭合、send_queue 快照差 = ACK 进度、
  DNS 自检与 Go 逐字节对齐）经评审者与本会话各自独立对源码核对，结论一致：闭合。
- 主会话点名三条 CC 正确性重点的评审结论：
  1. **seq 回退假阳性面**：出站 payload 赋值仅两处；RTO 回卷与 fast-retransmit
     是真阳性；**keep-alive 单字节段（seq−1+1B）是唯一假阳性源**——当前全仓
     `set_keep_alive` 0 命中（隐式前提，评审要求显式化）；
  2. **窗口上界**：三处增长律全 `.min(CWND_MAX)`；`take` 恒含 `allowed = cwnd−q`
     ⇒ pacing 不构成 cwnd 旁路；f64 饱和 fail-safe；
  3. **快照差观测**：flow socket 的 `send_slice` 全仓唯一（无旁路写）；tx_buffer
     只被 ACK 出队 ⇒ 差值恒 = ACK 进度；部分写 `q+w` 正确。反例（低）：
     `reset()` 清空 tx_buffer 会记成伪 ACK（dead flow 上无害）。
- 中危 2：①clippy 门禁红 3 处（ci-local 必红）；②判据可追溯性/判别力
  （A 单流/B 门关闭也过、0.4MB/s 基数不可复现、`#[ignore]` 理由与实测不符、
  重载下绝对阈值假红）。另指出**真机验收缺口**（harness 绕过 WG encap 路径）。
- 低-中：`LOSS_ACK_STALL=25ms` 与 smoltcp RTO 下限（10ms）耦合——RTT≲20ms 链路
  首次真丢包的停滞可能 <25ms 被滤（减窗晚一两拍非漏检；真机 26ms 形态踩线通过）。
- 低危 5：keep-alive 前提注释、Closed 态伪 ACK、注释措辞（「新写入 ≤ cwnd−q」）、
  serve flag 缺值静默 + `--listen 0` 未拒（Go 拒 1-65535）+ 零测试、DNS 测试
  `q[2..4]` 缺断言 + 分解消息写错 + `malformed=1` 子串断言脆、
  `dial_fail_seen` 键含源端口（探测源端口轮换 ⇒ 降噪失效）+ UDP 面口径不一致、
  `Flow` CC 字段可抽结构体（过度设计评价：中低）。
