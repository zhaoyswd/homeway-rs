# 端点学习与 DDNS 整改（2026-10-21）

## 复核与技术评审（开工前）

基线 `708c95b`，源仓开工时干净。F6/F7 仍成立：VPN 丢弃域名候选；宿主会话仅启动同步解析；App 与 daemon 的 endpointCacheDir 均未消费。

实现者方案：VPN/服务共用按 peerID 的有界候选表，保留 token/hint/probe/inband 来源与 TTL、认证成功时间及失败退避；线索仅为候选，只有岛完成 RPK 钉定与注册准入才标验证。认证成功落盘，0600 临时文件原子替换；坏缓存忽略，不影响 token。域名首次与恢复轮异步单飞解析 A/AAAA，已有候选立即起跑，失败保留旧有效结果，不增加恢复动作预算；无候选首次启动只在既有 3s DNS 总预算内等结果。全进程后台工作与解析线程有界，不新增独立常驻线程。

评审者检查：
- 对齐完整性：两种 App 模式与 daemon 共用目录；来源不冒充验证，缓存不存凭证。
- 边界：每 peer 最多 64 项，文件尺寸上限；拒绝零端口、unspecified/multicast/broadcast，LAN/回环测试可用；新线索不能挤掉 token/已验证项。
- 并发：岛回调仅更新内存/投递；DNS 与磁盘 IO 在有界后台单飞执行；每轮 DNS 使用一个总 deadline。
- 错误面：DNS/磁盘失败保留旧有效候选、不中止现有连接；所有候选仍须真实 TLS/准入认证。
- 漂移：来源治理重新恢复而非复活 WG 栈；具体 TTL/容量/退避属新明确行为，主任务同步 tier 连接真源。

技术门结论：按上述边界实施，岛回调与恢复取候选接口由岛任务同步接线。

## 实现与验证

实现位置：`facade/endpoint_candidates.rs`；VPN `tun_exec`、服务 `service_exec/host_session`、daemon `hosts` 已真实接线并消费 endpointCacheDir。岛的 CandidateHooks 每轮恢复立即取快照并启动后台刷新，DNS 完成通过 SetCandidates 更新同 peer 的活岛。两个 App 模式读写同一个 peer 文件，进程内共享内存表，跨进程以原子替换避免半文件。

现行常量：每 peer 64 项、缓存输入最大 64KiB、未验证 Hint/Probe 300s、DNS 600s、最近认证记录 7 天；失败按 2/4/8/16/32/64s 暂停实际投出（全表均冷却时保留最早到期的一项，避免删空；直连仍在冷却而中继未冷却时允许暂用中继，窗过后直连重新参与周期升级/重赛）；每表单飞、全进程后台任务最多 8 个，系统 DNS 沿用既有分档线程池。首次无候选最多等 3s DNS；已有候选/恢复不等；后台发现另给最多 250ms 总预算，向最多两个 token 直连地址发送现有 nonce UDP probe 以采集列表。DNS 空答/失败保留旧有效结果，成功变更替换未验证旧结果并保留仍在认证 TTL 内的旧地址供回落。

安全边界：token 不落缓存；可恢复的候选记录仅认证成功后写盘（0600/create_new 临时文件 + fsync + rename）；Hint/Probe/DNS 单独出现只进未验证内存表；失败沿另外保存有界冷却元数据，加载时只应用到当前 token、认证缓存或随后 DNS 得到的同址候选，绝不靠元数据创建候选。成功/失败写入合并进同一短命单飞 worker（50ms合并窗），不在岛内刷盘。IPv4 mapped 统一为 IPv4，防 unspecified/multicast/broadcast 绕过过滤；LAN 地址允许。未验证新线索不能挤掉 token/已验证项，在途候选被线索挤掉后真实认证成功会重新收录。缓存是加速线索，磁盘/线程资源失败不能阻塞或破坏既有连接。

线协议边界：现行 QUIC reg4/Probe STREAM 不含带内端点广播。本批真实来源为 Token/DNS、relay Hint、UDP Probe 列表；VerifiedPath 来源用于真实采纳沿回补在途被淘汰的候选；Inband 枚举仅保留类型接口，带内广播仍未实现，没有新增隐含 wire 协议，也不把明文端点列表当身份证明。

## 代码评审（完工后）

评审者按清单逐项复核：
- 对齐完整性：App VPN 与服务两消费面、daemon 面均消费缓存目录；恢复不再使用启动时固定名册；Hint/Probe 均有生产入口。失败冷却真实减少投出候选数，候选快照纯读接口供在飞赛跑有界合并新DNS结果，不重复启动DNS。
- 边界：数量/输入字节/TTL/重试退避/后台并发均有上限；认证地址与传闻地址分离；跨模式通知不互相覆盖，最多维护 8 个活岛通知口并清理已关闭口。
- 并发：岛回调仅更新短临界区并调度有界单飞后台；文件 IO/域名解析/UDP probe 不在岛线程执行；dirty 在收尾沿到达会由释放单飞槽后承接，磁盘失败不形成无限重试线程。
- 错误面：损坏/旧格式/超大缓存忽略；解析失败不删旧有效结果；缓存写失败不阻断网络；所有候选仍重做 RPK/准入。
- 漂移：明文 probe 的 fresh nonce 只证明地址可达，仍不写 verified；token 凭据不进入文件；新 TTL/容量明确登记待同步 tier 行为真源。
- Go 直译痕迹：没有恢复 WG 缓存接口或复制 Go 包树；共享 typed source、候选表与 std-only hook，无新增 runtime/常驻线程，无字符串错误类型外泄。

结论：本子任务代码门通过，无已知高危未决项。真实真机与私有出口的端到端验收由主任务整批执行；本子任务未动生产、未提交。
